AI Recap architecture: current and target

Updated 2026-11-09 (UTC), after the native ingestion cutover. Labels: native = code in this repo, n8n = legacy n8n workflow, planned = not built yet.

1. At a glance

  • One repo holds the website and the backend jobs. It is a Next.js App Router app on Netlify. Jobs are Netlify functions in netlify/functions/, and their logic is in src/pipeline/.
  • The data is in Postgres on Neon (Free plan), schema newsletter. Prisma is the client.
  • Native now: story ingestion, the approval board, and publish detection. n8n still does one stage: drafting (issue text, featured image, GHL email template).
  • The owner sends each campaign by hand in GoHighLevel (GHL). GHL emails the subscribers. The site publishes the issue when the sent email reaches a seed inbox.
  • Target: drafting moves to native code (Phase 5). Then n8n is switched off and the schema is cleaned up (Phase 6).

14. Rules and traps

  • Literal schedules. Netlify reads config.schedule from the function's source text. An imported constant deploys the function with no schedule. src/pipeline/netlify-functions-bundle.test.ts checks this and included_files.
  • Production DB. Never run tests or jobs against it. Use the Neon dev branch. Production schema changes go through scripts/run-prisma-prod.mjs, additive only while n8n reads the tables.
  • n8n is frozen. Read-only, except cutover or emergency fixes with the owner's OK. Do not trigger its webhooks. Do not commit on the board from a preview or local build: the commit route calls production n8n.
  • Netlify credits. Each production deploy costs 15 of 300 credits a month. Run npm run verify before you push. Docs-only merges put [skip netlify] in the squash subject.
  • Builds need APP_ENV. Local: APP_ENV=development npm run build. No secrets, subscriber data, or security details in the repo; it is public.
