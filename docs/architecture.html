AI Recap architecture

How the system works now. For plans, see GitHub issues. For history, see git and the ADRs.

1. At a glance

  • One repo holds the website and the pipeline jobs. It is a Next.js App Router app on Netlify. Jobs are Netlify functions in netlify/functions/, and their logic is in src/pipeline/.
  • The data is in Postgres on Neon (Free plan), schema newsletter. Prisma is the client.
  • Each weekday: the ingest job collects stories, the owner picks them on the board and commits, the draft job writes the issue, the owner reviews the draft in the app and stages it for sending with one click, the owner sends the staged email in GoHighLevel (GHL), and the publish job puts the issue on the site when the sent email reaches the seed inbox.
  • The run-checks job tests outcomes three times a day and posts incidents to the ops chat.
  • n8n is retired. Its workflows are disabled and kept as a record (ADR 0003). Never call or change them.

3. Jobs (Netlify functions)

Netlify cron is UTC only, so each job checks New York time in code. Scheduled functions stop at 30 s. Background functions (-background suffix) stop at 15 min.

run-checks0,5 14,15,16,17,22,23 * * 1-510:05, 12:00, 18:00 New York on weekdays (1 min early to 4 min late); outside production, a run at any other time ("Run now") is a full 18:00 passOutcome checks raise or resolve incidents; at 18:00 the daily summary to the ops chat, then the Healthchecks.io ping. Each outside call gets 5 s; Telegram and site calls stop 20 s into the run. runChecks() in src/pipeline/checks/run-checks.ts

Each run writes pipeline_runs (job, trigger, status, stats) and pipeline_events (step log). Job tokens: src/server/job-token.ts, format <expiresAtMs>.<sig>, HMAC key derived from SESSION_SECRET per purpose.

Incidents: run-checks raises ingest-run-missing, stories-thin, source-empty:<source>, commit-missing, draft-missing, publish-pending and site-check-failed, each ending in the New York date (CHECK_INCIDENT_PREFIXES in src/pipeline/checks/checks.ts). The draft job raises draft.failed:<date>. "Stage for sending" raises stage.failed:<date>, which run-checks closes when its day is over. All go through src/pipeline/notify/ (raiseIncident, which calls raiseAlert): one open alerts row per key, posted to the ops chat in production only. What each key means and what to do: pipeline runbook. Open incidents are on /admin/incidents.

Scheduled functions fire only on the production deploy. To try a job on a deploy preview (Neon dev), use "Run now" on the preview's function page in Netlify.

APP_ENV is set in netlify.toml and also as a Netlify env var with the same value per context, because functions cannot read netlify.toml values at runtime. Next routes get the build's value inlined (next.config.mjs env), so they must read process.env.APP_ENV by name, never process.env whole.

Guards: src/pipeline/side-effects/ gates the distribution service (GHL), S3, and the review group (record-only outside production; S3 only under newsletter-dev/). src/pipeline/notify/ sends ops alerts only in production.

9. Rules and traps

  • Literal schedules. Netlify reads config.schedule from the function's source text. An imported constant deploys the function with no schedule. src/pipeline/netlify-functions-bundle.test.ts checks this and included_files.
  • Test a new job on a deploy preview before merging. A local bundle can load packages from the repo's node_modules, so it can pass while the Netlify bundle fails. netlify.toml ships @prisma/client-runtime-utils with the jobs for this reason.
  • Production DB. Never run tests or jobs against it. Use the Neon dev branch. Production schema changes go through scripts/run-prisma-prod.mjs, with the owner.
  • Netlify credits. Each production deploy costs 15 of 300 credits a month. Run npm run verify before you push. Docs-only merges put [skip netlify] in the squash subject.
  • Netlify env vars. A secret must use scopes builds, functions, and runtime (Free plan). Functions read env vars at deploy time, so a changed value needs a new deploy. The Netlify API returns a secret's value masked, so a script cannot read or test it; test with the .env.local copy.
  • Builds need APP_ENV. Local: APP_ENV=development npm run build.
  • The repo is public. No secrets, subscriber data, or security details in it.
